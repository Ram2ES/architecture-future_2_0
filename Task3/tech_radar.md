# Технологический радар «Будущее 2.0»

Визуализация радара: `tech_radar.drawio`

## 1. Методы

### Adopt

| Технология | Статус | Бизнес-сценарии |
|------------|--------|-----------------|
| Data Mesh | Новая | Независимое развитие доменов (клиники, финтех, ИИ). Подключение партнёров без изменений в DWH. Решает P1, P4, P9 из Task1 |
| Event-Driven Architecture | Новая | Асинхронный обмен между доменами. Финтех получает события об услугах в реальном времени. ИИ получает данные для анализа без задержек |
| Data Products | Новая | Каждый домен публикует готовые витрины. Портал самообслуживания строит отчёты поверх Data Products, а не поверх сырых таблиц DWH |
| Infrastructure as Code | Новая | Воспроизводимое развёртывание доменных сред в облаке. Быстрое подключение нового партнёра по шаблону |
| CI/CD | Новая | Независимые релизные циклы доменов. Финтех деплоит без блокировки клиник |

### Trial

| Технология | Статус | Бизнес-сценарии |
|------------|--------|-----------------|
| CQRS | Новая | Разделение чтения и записи в доменах с высокой нагрузкой (финтех-транзакции, клинические записи). Решает P7 - разделение OLTP/OLAP |
| Feature Store | Новая | Централизованное хранение признаков для ML-моделей. Ускоряет обучение новых моделей в ИИ-домене |

### Assess

| Технология | Статус | Бизнес-сценарии |
|------------|--------|-----------------|
| Data Contracts | Новая | Формальные SLA между доменами. Гарантия качества данных при масштабировании на новых партнёров |
| Chaos Engineering | Новая | Проверка отказоустойчивости доменной архитектуры. Критично для медицинских и финансовых сервисов |

### Hold

| Технология | Статус | Бизнес-сценарии |
|------------|--------|-----------------|
| Монолитный DWH как центр логики | Текущая | Все сценарии страдают. DWH переводится в read-only, логика выносится в домены |
| Синхронная интеграция через единую шину (ESB) | Текущая | Тормозит финтех и ИИ. Функции ESB декомпозируются между Kafka (транспорт), API Gateway (ФЛК), Airflow (ETL) и доменными сервисами (интеграции) |

## 2. Платформы

### Adopt

| Технология | Статус | Бизнес-сценарии |
|------------|--------|-----------------|
| Apache Kafka | Новая | Асинхронный транспорт событий между доменами (замена транспортного слоя ESB). Масштабируется под рост нагрузки финтех-транзакций и потока мед. данных для ИИ. Решает P5 (транспорт) |
| Облачная инфраструктура (Kubernetes) | Новая | Масштабирование ресурсов под каждый домен. GPU для ИИ, отказоустойчивость для финтеха, геораспределение для клиник |
| PostgreSQL (доменные БД) | Новая | Замена SQL Server 2008 для операционных данных доменов. Открытая лицензия, активная поддержка, cloud-native |
| Keycloak (IAM) | Новая | SSO и ролевой доступ. Изоляция мед. данных от финтех-сотрудников и наоборот. Решает P6 |
| S3-совместимое хранилище | Новая | Объектное хранилище для мед. изображений (рентген, МРТ), передаваемых в ИИ-домен |

### Trial

| Технология | Статус | Бизнес-сценарии |
|------------|--------|-----------------|
| ClickHouse / аналитическая СУБД | Новая | OLAP-движок для быстрой аналитики в портале самообслуживания. Решает P7 - отчёты за секунды вместо часов |
| DataHub | Новая | Каталог данных, lineage, метаданные. Бизнес-пользователи находят нужные данные самостоятельно. Решает P8 |
| Apache Airflow | Новая | Оркестрация ETL/ELT-пайплайнов: трансформация данных из операционных БД в Data Products, загрузка в ClickHouse, миграция из Legacy DWH. Берёт на себя функцию трансформации, которая ранее выполнялась в ESB (Apache Camel). Решает P5 (частично) |

### Assess

| Технология | Статус | Бизнес-сценарии |
|------------|--------|-----------------|

### Hold

| Технология | Статус | Бизнес-сценарии |
|------------|--------|-----------------|
| SQL Server 2008 | Текущая | Снят с поддержки, уязвимости. Переводится в read-only, данные мигрируются в доменные БД. Решает P2 |
| Apache Camel | Текущая | ESB - узкое место. Функции декомпозируются: транспорт → Kafka, ФЛК → API Gateway, ETL/трансформация → Airflow, интеграции → доменные сервисы. Решает P5 |

## 3. Инструменты

### Adopt

| Технология | Статус | Бизнес-сценарии |
|------------|--------|-----------------|
| Портал самообслуживания (Apache Superset / Metabase) | Новая | Прямое требование бизнеса. Конструктор отчётов, дашборды. Пользователи строят отчёты без BI-команды. Решает P3 |
| API Gateway (Kong / Envoy) | Новая | Единая точка входа. Маршрутизация запросов к доменам. Стандартизированный доступ для партнёров |
| Terraform | Новая | IaC для облачной инфраструктуры. Шаблонное развёртывание доменных сред |
| MLflow | Новая | Версионирование ML-моделей, трекинг экспериментов. Ускоряет цикл обучения ИИ-моделей для диагностики |

### Trial

| Технология | Статус | Бизнес-сценарии |
|------------|--------|-----------------|
| Prometheus + Grafana | Новая | Мониторинг доменных сервисов. SLA для медицинских и финансовых систем |
| Great Expectations | Новая | Автоматическая проверка качества данных в Data Products |

### Hold

| Технология | Статус | Бизнес-сценарии |
|------------|--------|-----------------|
| Power BI (с кастомизациями поверх DWH) | Текущая | Тяжёлые кастомизации, привязка к DWH. Заменяется порталом самообслуживания поверх Data Products |
| PowerBuilder | Текущая | Клиентский интерфейс оператора. Редкая технология, сложно нанимать. Заменяется веб-интерфейсом |

## 4. Языки и фреймворки

### Adopt

| Технология | Статус | Бизнес-сценарии |
|------------|--------|-----------------|
| Python (ИИ-домен) | Текущая | Основной стек ИИ-сервисов. ML-модели, анализ изображений, предиктивная аналитика |
| Golang (финтех-домен) | Текущая | Высокопроизводительные финтех-сервисы. Скоринг, обработка транзакций |
| Java (финтех-домен) | Текущая | Бизнес-логика финтех-сервисов. Кредитование, интеграция с ЦБ |
| TypeScript (фронтенд) | Новая | Веб-интерфейс для операторов клиник (замена PowerBuilder) и портал самообслуживания |

### Hold

| Технология | Статус | Бизнес-сценарии |
|------------|--------|-----------------|
| PowerBuilder | Текущая | Устаревший стек. Нет специалистов на рынке. Заменяется TypeScript веб-приложением |
| T-SQL (хранимые процедуры в DWH) | Текущая | Бизнес-логика в хранимых процедурах. Выносится в доменные сервисы |
